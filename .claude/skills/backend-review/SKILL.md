# Backend 코드 리뷰

백엔드 코드의 품질과 아키텍처 준수 여부를 검토합니다. 리뷰만 하고 코드 수정은 하지 않습니다.

## Instructions

### 1. 계층 분리 검토
- [ ] Controller에 비즈니스 로직이 없는가?
- [ ] Service에 비즈니스 로직이 집중되어 있는가?
- [ ] Domain에 side-effect가 없는가?
- [ ] 역방향 의존성이 없는가?

### 2. 네이밍 규칙
- [ ] DTO 네이밍이 컨벤션을 따르는가? (List/Get/Create/Update/Delete)
- [ ] Service 메서드명이 컨벤션을 따르는가?
- [ ] API 경로가 클래스 레벨 없이 메서드에 직접 지정되어 있는가?

### 3. 에러 처리
- [ ] 에러 메시지가 한국어로 작성되어 있는가?
- [ ] 적절한 예외 타입을 사용하고 있는가?

### 4. 기타
- [ ] 불필요한 코드가 없는가?
- [ ] ktlint 규칙을 준수하고 있는가?

## 출력 형식

```markdown
## 리뷰 결과

### 잘된 점
- [내용]

### 개선 필요
- [파일:라인] [문제점] - [개선 방안]

### 권장 사항
- [내용]
```

## 역할 범위

- **O**: 코드 검토, 문제점 지적, 개선 방안 제시
- **X**: 코드 직접 수정 (별도 skill 사용)
