# 운영진 문자 발송 화면 구현

## 작업 개요

`Sight-Legacy`의 `/manage/sms` 화면을 새 프론트엔드에 재구현한다. 운영진이 회원 또는 직접 입력한 전화번호를 수신자로 지정하고, 메시지를 작성하여 동아리 운영 목적의 문자를 발송할 수 있는 운영진 전용 화면을 제공한다.

문자 발송의 권한과 비즈니스 판정은 [운영진 문자 발송 Backend Task](./member-sms-backend.md)와 [문자 발송 정책](../../policy/문자_발송/POLICY.md)을 따른다. 이 Task는 사용자에게 보이는 화면 흐름과 입력·결과 경험만 정의한다.

작업이 완료되면 운영진은 `/manage/sms`에서 회원 목록을 확인하고, 회원 및 직접 입력 수신자를 선택하고, 메시지를 작성하고, 서버가 반환한 수신자별 발송 결과와 SMS/LMS 유형을 확인할 수 있어야 한다.

## 사용자와 목표

- 대상 사용자는 운영진이다.
- 운영진은 동아리 운영에 필요한 공지나 안내를 여러 회원에게 문자로 전달하기 위해 이 기능을 사용한다.
- 운영진은 회원 목록에서 수신자를 선택하거나 회원이 아닌 전화번호를 직접 입력할 수 있다.
- 운영진은 메시지의 바이트 수와 SMS/LMS 자동 전환 기준을 발송 전에 이해할 수 있어야 한다.
- 운영진은 발송 후 수신자별 성공·실패 결과와 실제 발송 유형을 확인할 수 있어야 한다.

## 사용자 경험 계약

- 운영진은 `/manage/sms` 경로에서 문자 발송 화면에 진입한다.
- 운영진이 아닌 사용자가 해당 경로에 진입하면 운영진 전용 페이지를 노출하지 않고 기존 운영진 페이지 접근 제한 흐름을 따른다.
- 화면 진입 시 회원 수신자 목록과 공식 발신번호를 조회한다.
- 회원 목록에는 현재 회원으로 관리되고 있으며 교류 회원이 아닌 회원을 표시한다.
- 정지 상태 회원은 회원 목록에서 선택할 수 있다.
- 회원 목록은 이름을 기준으로 정렬하고, 각 회원의 이름·소속·입회 정보·전화번호 등록 여부를 확인할 수 있게 한다.
- 운영진은 회원 항목을 선택하거나 해제할 수 있으며 현재 선택된 회원 수를 확인할 수 있다.
- 운영진은 이름을 입력하여 회원 목록을 좁혀 볼 수 있다.
- 운영진은 회원 외 수신번호를 쉼표로 구분하여 추가할 수 있다.
- 메시지 입력란에는 `[쿠러그]`와 `(발신 전용)`을 포함한 기본 문구를 제공한다.
- 메시지 입력 중 현재 메시지의 바이트 수를 표시한다.
- 화면에는 90바이트 이하이면 SMS, 90바이트를 초과하면 LMS로 자동 전환된다는 안내를 표시한다.
- SMS/LMS를 운영진이 직접 선택하는 입력 요소는 제공하지 않는다.
- `{realname}` 치환이 지원된다는 안내를 표시한다.
- 발송 전에는 선택된 회원 수, 추가 수신번호 및 메시지 내용을 확인할 수 있어야 한다.
- 발송이 시작되면 같은 요청을 중복 실행하지 않도록 발송 동작을 제한한다.
- 전체 발송 성공 시 성공 상태와 수신자별 발송 결과를 표시하고, 입력 화면으로 돌아갈 수 있게 한다.
- 일부 수신자만 성공하면 성공·실패 수신자를 구분하여 표시하고, 실패한 수신자와 오류 메시지를 확인할 수 있게 한다.
- 일부 실패 결과를 확인한 뒤 운영진은 실패 수신자를 검토하여 새 요청으로 다시 발송할 수 있다. 화면은 자동으로 재발송하지 않는다.
- 발송 요청이 외부 서비스 오류로 처리되지 않은 경우 작성한 수신자와 메시지를 유지하여 운영진이 결과를 확인하거나 취소할 수 있게 한다.
- 화면을 이탈하거나 새로고침하면 작성 중인 메시지를 복구하지 않는다.

## 허용 및 제한 정책

### 운영진 전용 접근

- 주체: 사이트 사용자
- 조건: 문자 발송 화면 또는 문자 발송 API에 접근하려고 함
- 행동: 문자 발송 화면을 열거나 문자 발송을 실행함
- 판정: 조건부 허용
- 허용 예외: 운영진인 경우에만 허용
- 사용자에게 보이는 처리: 운영진은 화면을 사용할 수 있고, 운영진이 아닌 사용자는 운영진 전용 화면을 노출하지 않으며 발송을 실행할 수 없게 한다.
- 보장 계층: Frontend와 Backend
- 안내 및 회복: 운영진 권한이 없는 사용자는 문자 발송을 수행할 수 없으며, 필요한 경우 운영진 권한이 부여된 계정으로 다시 접근한다.

### 회원 수신자 지정

- 주체: 운영진
- 조건: 회원 목록에서 수신자를 선택함
- 행동: 회원을 문자 수신자로 추가하거나 해제함
- 판정: 조건부 허용
- 허용 예외: 현재 회원으로 관리되고 있으며 교류 회원이 아닌 회원만 허용
- 사용자에게 보이는 처리: 허용되지 않는 회원은 목록에 표시하지 않으며, 서버가 다시 거부한 회원은 발송 대상에서 제외하고 이유를 표시한다.
- 보장 계층: Frontend와 Backend
- 안내 및 회복: 회원 상태가 변경된 경우 회원 목록을 새로 조회한 뒤 현재 허용되는 회원을 선택한다.

### SMS/LMS 유형 선택

- 주체: 운영진
- 조건: 문자 메시지를 작성하거나 발송함
- 행동: SMS 또는 LMS 유형을 직접 선택하거나 자동 전환 기준을 우회함
- 판정: 금지
- 허용 예외: 없음
- 사용자에게 보이는 처리: 유형 선택 요소를 제공하지 않고, 90바이트 초과 시 LMS로 자동 전환된다는 기준만 안내한다.
- 보장 계층: Frontend와 Backend
- 안내 및 회복: 실제 발송 유형은 서버가 최종 메시지 기준으로 결정하며, 발송 결과에서 수신자별 유형을 확인할 수 있다.

### 문자 발송 실행

- 주체: 운영진
- 조건: 메시지가 비어 있지 않고 유효한 수신자가 하나 이상 있음
- 행동: 문자 발송을 실행함
- 판정: 조건부 허용
- 허용 예외: 유효한 수신자가 없거나 메시지가 비어 있으면 허용하지 않음
- 사용자에게 보이는 처리: 발송 버튼을 실행할 수 없게 하거나 입력 오류를 표시하고, 서버 거부 시 입력값을 유지한 채 오류를 표시한다.
- 보장 계층: Frontend와 Backend
- 안내 및 회복: 메시지와 수신자를 수정한 뒤 다시 실행할 수 있다.

## 입력 및 복구

- 회원 선택은 회원 ID를 기준으로 요청하며, 화면에 표시된 이름만으로 수신자를 확정하지 않는다.
- 직접 입력 수신번호는 쉼표로 구분한다. 공백·하이픈·괄호가 포함된 입력도 서버의 정규화 결과를 기준으로 처리한다.
- 메시지 입력이 비어 있으면 발송 요청을 실행하지 않고 입력란에 오류를 표시한다.
- 수신자가 한 명도 선택되지 않았으면 발송 요청을 실행하지 않고 회원 선택 또는 추가 수신번호 입력을 안내한다.
- `{realname}`은 회원 수신자에게 회원 이름으로 치환되며, 직접 입력 수신자에게는 전화번호 표시값으로 치환된다는 안내를 제공한다.
- 90바이트 경계는 화면의 참고 정보이며, 최종 SMS/LMS 판정은 서버 응답을 기준으로 한다.
- 발송 중에는 입력값과 수신자 선택을 변경하거나 같은 요청을 다시 제출할 수 없게 한다.
- 전체 성공 후에는 발송된 입력을 초기화할 수 있는 새 작성 흐름을 제공한다.
- 부분 성공 후에는 기존 입력과 결과를 함께 확인할 수 있어야 하며, 실패 수신자만 다시 선택하여 새 발송 요청을 만들 수 있다.
- 실패한 요청을 자동 재시도하지 않는다.

## 데이터 및 연동

- 회원 목록과 공식 발신번호는 `GET /manager/sms`에서 조회한다.
- 공식 발신번호 변경은 `PUT /manager/sms/sender-phone`을 사용한다.
- 문자 발송은 `POST /manager/sms`를 사용한다.
- request·response field와 상태 코드는 [운영진 문자 발송 Backend Task](./member-sms-backend.md)를 단일 계약으로 사용하며, 이 문서에서 다시 정의하지 않는다.
- 서버가 반환하는 수신자별 `type` 값(`SMS` 또는 `LMS`)을 실제 발송 유형으로 표시한다.
- `207 Multi-Status` 응답에서는 성공·실패 결과를 모두 표시하고, `400`, `401`, `403`, `502`, `503` 응답은 서버가 반환한 한국어 오류를 기준으로 처리한다.
- 발신번호 변경이 성공하면 화면의 공식 발신번호를 갱신한다.
- 회원 목록 조회가 실패하면 발송 입력을 활성화하지 않고 다시 조회할 수 있게 한다.
- 발송 API가 제공된 뒤 화면을 배포한다. 새 화면은 발송 API가 없는 환경에서 발송을 시도하지 않는다.
- 기존 레거시 화면과 새 화면을 동시에 사용하면 중복 발송이 발생할 수 있으므로 운영 전환 시 하나의 발송 경로만 사용한다.

## 사용자 보호 및 개인정보

- 운영진에게만 회원 전화번호를 표시하며, URL query parameter나 browser local storage에 저장하지 않는다.
- 직접 입력 전화번호와 메시지 내용은 URL에 포함하지 않는다.
- 메시지와 전화번호를 별도 임시 저장하거나 자동 복구하지 않는다.
- 발송 버튼 실행 전 현재 선택된 수신자와 메시지 내용을 화면에서 확인할 수 있어야 한다.
- 외부 발송은 비용과 되돌릴 수 없는 알림을 발생시키므로, 발송 중복 실행을 막는다.
- 서버가 반환한 오류에 포함된 외부 서비스 인증 정보나 내부 상세 정보는 화면에 표시하지 않는다.

## 접근성 및 사용 환경

- 회원 선택, 추가 수신번호, 메시지 입력, 발송 및 공식 발신번호 변경은 키보드만으로 사용할 수 있어야 한다.
- 선택된 회원 수, 메시지 바이트 수, SMS/LMS 자동 전환 기준 및 발송 결과는 색상이나 아이콘만으로 전달하지 않는다.
- 부분 성공 결과는 성공과 실패를 텍스트로 구분하고, 실패 이유를 보조기기가 읽을 수 있어야 한다.
- 긴 회원 목록과 긴 메시지는 좁은 화면에서도 입력 영역과 발송 결과를 확인할 수 있어야 한다.
- 메시지의 한글·영문 혼합 입력과 90바이트 경계에서도 바이트 수 안내가 갱신되어야 한다.

## 검증

- 운영진이 `/manage/sms`에 진입하여 회원 목록과 공식 발신번호를 확인할 수 있는지 검증한다.
- 비운영진이 화면에 접근하거나 발송할 수 없는지 검증한다.
- 교류 회원이 회원 수신자 목록에 표시되지 않고 정지 상태 회원은 선택할 수 있는지 검증한다.
- 회원 선택·해제, 이름 검색 및 선택된 회원 수 표시가 일치하는지 검증한다.
- 직접 입력한 여러 전화번호가 쉼표 기준으로 처리되고 입력 안내가 표시되는지 검증한다.
- 빈 메시지와 수신자 없는 상태에서 발송이 차단되는지 검증한다.
- 메시지 바이트 수가 입력에 따라 갱신되고 90바이트 이하·초과 기준 안내가 표시되는지 검증한다.
- SMS/LMS 수동 선택 요소가 없고, 서버 결과의 수신자별 `type`이 표시되는지 검증한다.
- `{realname}` 치환 안내가 표시되고 회원·직접 입력 수신자를 함께 발송할 수 있는지 검증한다.
- 발송 중 중복 제출이 차단되는지 검증한다.
- 전체 성공, 부분 성공, 유효하지 않은 입력, 권한 오류 및 외부 서비스 오류가 각각 구분되어 표시되는지 검증한다.
- 부분 성공 후 성공·실패 수신자를 확인하고 실패 수신자만 새 요청으로 재선택할 수 있는지 검증한다.
- 오류 발생 후 수신자와 메시지 입력이 의도하지 않게 초기화되지 않는지 검증한다.
- 전화번호와 메시지가 URL·local storage·의도하지 않은 화면 영역에 노출되지 않는지 검증한다.
- 키보드 탐색, focus 이동, screen reader용 상태 안내 및 좁은 화면 사용성을 검증한다.
- 프론트엔드 lint와 build를 실행한다.
